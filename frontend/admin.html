OPERATING NOTES

Admin instructions

  • This page shows names, email addresses, signup times, and account status—not passwords, reset tokens, or session secrets.
  • Block an account only when necessary. Blocking prevents sign-in and ends the user's active sessions; you can unblock the account here.
  • The app continues serving weather and account requests when you are signed out. Admin access is only needed for oversight.
  • Keep the administrator login private, use a unique strong password, and sign out on shared devices.
  • The sole administrator must have the database admin role and an email matching ADMIN_EMAIL. Provision it with the private bootstrap token; an email match alone does not grant access. Never put either setting in frontend configuration. The administrator username is always shauAdmin.
  • If you change the administrator account's email, update ADMIN_EMAIL in the deployment environment too, or admin access will stop working.
  • Use the hosting provider's secret manager for API keys and credentials. Rotate anything that may have been exposed.
  • Before releases, check service health, backups, logs, and the deployment checklist in the project documentation.
